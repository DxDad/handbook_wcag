## Manifesto

> Identifiquei uma barreira. E agora, como resolvo?

O Handbook nasceu para responder a essa pergunta. Reúne experiências de produto, design, desenvolvimento, arquitetura, qualidade e gestão para aproximar as diretrizes de acessibilidade do trabalho cotidiano.

Comece pelo que você observou. Talvez o teclado não chegue a um controle, ou um leitor de tela anuncie um botão sem informar sua função. O guia relaciona o sintoma a causas prováveis, referências técnicas, sugestões de correção e formas de testar o resultado. As normas continuam sendo a referência para avaliar a conformidade.

## Para quem é

**Produto e design** podem usar o guia para entender o impacto das barreiras e decidir o que priorizar. **Desenvolvimento e arquitetura** encontram caminhos para implementar as correções. **Qualidade (QA)** encontra orientações para reproduzir o problema e validar o resultado.

## Como o Handbook ajuda

## Como o conteúdo é organizado

O catálogo tem dois filtros que você pode usar juntos ou separadamente.

- **Categoria** indica o tipo de problema, como teclado e foco, leitor de tela ou formulário.
- **Componente** indica o elemento da interface em que o problema aparece, como botão, modal ou imagem.

Por exemplo, selecione a categoria **Teclado e foco** e o componente **Modal** para encontrar problemas de navegação pelo teclado em janelas modais. Um mesmo sintoma pode aparecer em mais de um componente.

## O que cada card contém

O card reúne o sintoma, as causas mais comuns, os passos de correção e as orientações de teste. Quando disponíveis, você também encontra exemplos de código e critérios das Diretrizes de Acessibilidade para Conteúdo Web (WCAG). Veja [como ler um card](./como-usar.mdx).

Cada sintoma tem uma página própria. Use **Copiar URL** no fim do card aberto ou da página individual para compartilhar o endereço.

## Como os dados são armazenados {/* #sobre-o-schema-de-dados */}

O arquivo [`data.json`](https://github.com/DxDad/handbook_wcag/blob/main/src/data/data.json) contém os sintomas. O [`schema.json`](https://github.com/DxDad/handbook_wcag/blob/main/src/data/schema.json) define quais campos são obrigatórios e quais valores eles aceitam. O exemplo abaixo mostra a estrutura de um registro.

```json
{
  "id": "tab-nao-acessa",
  "sintoma": "Não consigo acessar um componente usando Tab",
  "categoria": "teclado",
  "componentes": ["botao", "link"],
  "causas_provaveis": ["..."],
  "solucao_minima": ["..."],
  "validacao": ["..."],
  "impacto": "alto",
  "wcag": ["2.1.1", "2.4.3"]
}
```

Como os dados ficam em um arquivo separado da interface, podem ser reaproveitados em outros formatos, como uma planilha.
